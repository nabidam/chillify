Result: 4 failed, 2 passed. Representative failure:

  2) [chromium] › tests/e2e/accessibility.spec.ts:79:1 › Gate 3 — axe is clean across the reachable screen states

    Error: aria-input-field-name (serious) on S2 library
    ...
    +   Object {
    +     "id": "aria-input-field-name",
    +     "impact": "serious",
    +     "help": "ARIA input fields must have an accessible name",
    +     "nodes": Array [ ... target: [".w-24 > span:nth-child(2) > ..."] ... ]
    +   },

Root cause: frontend/src/features/player/PersistentPlayer.tsx passes
aria-label="Seek"/"Volume" to the Shadcn Slider wrapper (frontend/src/
components/ui/slider.tsx), which forwards it only to SliderPrimitive.Root;
Radix places role="slider" on SliderPrimitive.Thumb, which never receives a
name. Since PersistentPlayer is mounted on every screen, this reproduces on
every axe scan, on a clean checkout, with zero Task 18 changes applied —
confirmed by running the identical command against the unmodified
pre-existing accessibility.spec.ts (Task 14/15) before any Task 18 code
existed. A correct fix needs either the generated slider.tsx primitive
(CONVENTIONS reserves hand-edits of generated ui/ primitives for the Shadcn
CLI) or PersistentPlayer.tsx (owned by Tasks 2/13), neither in Task 18's
file list. Recorded as a finding in ARCHITECTURE's decision log rather than
silently fixed or silently hidden. scripts/verify/nfr.sh does not bundle
accessibility.spec.ts, so this task's own suite does not depend on it;
frontend/tests/e2e/firefox-smoke.spec.ts locates the seek control via
getByLabel("Seek").getByRole("slider") rather than by the thumb's own
(currently absent) accessible name.

======================================================================
4. Two additional pre-existing regressions discovered and fixed
   (both directly implicated by this task's own acceptance criteria;
   see ARCHITECTURE's 2026-07-26 decision log entries for detail).
======================================================================

- deploy/nginx.conf forwarded Host via $host (drops a non-default port),
  which broke MutationGuardMiddleware's same-origin check for every
  mutation on a non-default-port deployment (every gate stack, since all
  use CHILLIFY_BIND_PORT=8788). Fixed: $host -> $http_host. Confirmed by
  degraded.spec.ts's playlist-creation step, which failed with "This
  request's Origin is not permitted to change this deployment." before the
  fix and passes after (see run #2 above, all green).
- backend/src/chillify/infrastructure/logging/redaction.py's
  RedactingFilter never touched record.exc_info, so a secret folded into a
  raw exception message could reach real stdout through a Rich traceback.
  Fixed with _redact_exc_info; covered by the four tests in
  backend/tests/integration/test_secret_redaction.py (all passing, part of
  `backend tests` in run #1 above).
