=====================================================================
Recorded, not fixed: cleanup.sh shares the "chillify" project name
=====================================================================
While the full backend suite ran in the background, the real, running
`.gate/release` stack was unexpectedly torn down. Cause: this task's own new
tests (test_gate_environment_still_seeds_successfully,
test_release_environment_with_contained_roots_seeds_successfully) originally
called the real scripts/gate/cleanup.sh for teardown, which runs
`docker compose --env-file <that-test's-own-.env> down --volumes
--remove-orphans`. `compose.yaml` declares `name: chillify` unconditionally,
so every `docker compose` invocation in this repository resolves to the
identical project name regardless of which `.env` is passed — cleanup.sh's
down therefore targeted the live release stack's containers, not just the
test's own (never-launched) environment. Fixed within this task's own new
tests by removing the prepared directory tree directly (`_remove_tree`, no
`docker compose` call) instead of going through cleanup.sh, since these tests
never launch containers and have none to stop. cleanup.sh itself is
unmodified (out of this task's file list) and carries the same latent
behavior for any other caller that seeds a real `.env` and then calls it —
recorded here rather than silently fixed, matching this repository's existing
convention for out-of-scope findings. The release stack was rebuilt and
confirmed ready=true/environment=release immediately after.

Final state: the .gate/release docker stack was left running (CHILLIFY_ENV=release,
seeded), matching how it was found at the start of this task.
