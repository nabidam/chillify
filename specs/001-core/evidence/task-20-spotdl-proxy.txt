Task 20 — SpotDL proxy: argv flag -> child-environment export
================================================================

ROOT CAUSE (confirmed live, before the fix)
--------------------------------------------
SpotdlInspector.inspect and SpotdlAcquisitionProvider.acquire passed the saved
proxy as `--proxy <url>` on argv. That flag does not cover the requests/
urllib3 traffic spotdl uses internally (Spotify metadata, YouTube Music
connectivity preflight), which is exactly the traffic that needs the proxy on
a network with hijacked/broken DNS.

$ docker exec chillify-api-1 sh -c \
    '/opt/spotdl/bin/spotdl --proxy socks5://host.docker.internal:10808 url \
     "https://open.spotify.com/track/4PTG3Z6ehGkBFwjybzWkR8"'
...
ConnectionError: HTTPSConnectionPool(host='music.youtube.com', port=443): Max
retries exceeded with url: / (Caused by NameResolutionError(
"HTTPSConnection(host='music.youtube.com', port=443): Failed to resolve
'music.youtube.com' ([Errno -3] Temporary failure in name resolution)"))

Same command, proxy exported to the environment instead of argv (also proves
the socks5:// -> socks5h:// rewrite is required — DNS must resolve through the
proxy, not locally):

$ docker exec chillify-api-1 sh -c \
    'HTTP_PROXY=socks5h://host.docker.internal:10808 \
     HTTPS_PROXY=socks5h://host.docker.internal:10808 \
     /opt/spotdl/bin/spotdl url "https://open.spotify.com/track/4PTG3Z6ehGkBFwjybzWkR8"'
Processing query: https://open.spotify.com/track/4PTG3Z6ehGkBFwjybzWkR8
https://music.youtube.com/watch?v=lYBUbBu4W08


THE FIX
-------
backend/src/chillify/infrastructure/providers/spotdl.py:
  - `_proxy_for_child_env`: rewrites socks5:// to socks5h:// (http(s):// and
    already-socks5h:// pass through unchanged), using `parse_proxy` from
    infrastructure/security/outbound.py for scheme validation instead of
    writing a new URL parser.
  - `_child_env`: builds the child's full environment (a copy of this
    process's `os.environ` plus HTTP_PROXY/HTTPS_PROXY/http_proxy/
    https_proxy), or returns None (inherit unchanged) when no proxy is
    configured.
  - `_default_spotdl_runner` gained an `env` parameter passed straight to
    `subprocess.Popen(..., env=env)`.
  - `SpotdlInspector.inspect` and `SpotdlAcquisitionProvider.acquire` no
    longer append `--proxy` to argv; they pass `env=_child_env(proxy)` to the
    runner instead. The proxy — and any credential it carries — now never
    appears on the process argument vector, closing the `ps`-visible
    credential leak CONVENTIONS.md and ARCHITECTURE.md (~738) forbid.

Additional necessary change, discovered only during live verification:
`_INSPECT_TIMEOUT_SECONDS` was 60s, sized for the old failure mode (an
instant DNS-resolution error). With the proxy now actually carrying the
traffic, a full `spotdl save` round trip (Spotify metadata fetch + YouTube
Music connectivity preflight) took 122-140s over this operator's real proxy.
Raised to 180s, with deploy/nginx.conf's `/api/` `proxy_read_timeout` raised
from 60s to 200s to match (otherwise nginx cuts the response before the
backend's own timeout gets a chance to answer). Both changes are commented
in place with the measured timings that justify them.


TESTS ADDED (backend/tests/contract/test_spotdl_contract.py)
--------------------------------------------------------------
New class TestSpotdlProxyEnvironmentContract, plus updates to
TestSpotdlCliContract:
  - proxy absent from argv, inspect and acquire
  - proxy present in the child env, inspect and acquire
  - socks5:// -> socks5h:// conversion; socks5h:// and http(s):// unchanged
  - no proxy configured -> no env injected, no argv flag (env=None -> Popen
    inherits unchanged)
  - child still inherits PATH
  - a credentialed proxy never appears in a raised error message/context
